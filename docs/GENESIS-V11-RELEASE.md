# Genesis V11 certification and release

Status: implementation prepared; **SERVER_CERTIFIED: false; PRODUCTION_AUTHORIZED: false**.
No production migration, certificate issuance, player mutation, deployment or push is part of this local release preparation.

## Implemented contract

The deployed host retains `get_ares_genesis_placement_v10()` for compatibility. The new migration implements that RPC with authenticated membership checks and a service-owned V11 certificate registry. Anonymous callers cannot execute it. Players cannot inspect or write certificates or read the global world snapshot. Certificates require release/evidence SHA-256 digests, an HTTPS evidence location, a current world snapshot, complete site inventories, and a maximum 24-hour validity period. They are immutable except for one-way revocation. There are no seed certificates.

A successful review returns a maximum 60-second browser lease. The host checks the colony, release digest, evidence digest, server clock, lease and geometry, then independently evaluates the shipped terrain, foundation, ramp and collisions. It renews review every 12 seconds, serializes asynchronous reviews, and removes the campus before lease expiry or on failure. Failed scene loading preserves the original Hub. Flight code, flight assets and player/controller ownership are preserved.

The global snapshot includes all colony/building/catalog rows and a monotonic epoch. The epoch advances only while an unrevoked, unexpired certificate exists; an uncertified deployment adds no global epoch write to ordinary player actions. World writes invalidate approval, even when a building later returns to its previous coordinates. Issuance locks the world tables and rejects stale snapshots and existing campus conflicts. While a reservation is live, new conflicting building writes and footprint-catalog changes are rejected. Non-conflicting player writes continue; their epoch change requires recertification. Revocation retains reservation protection for 60 seconds, capped by certificate expiry, to drain outstanding browser leases. Renewal requires revoking the previous certificate and inserting a newly reviewed one in a transaction. One unrevoked world reservation is permitted.

The release manifest hashes paths and bytes under `src` and `public`, plus the package manifests, build configuration, manifest generator and certification migration. `node scripts/genesis-release-manifest.mjs --write` creates a new digest after an intentional change. This invalidates certificates for older releases; it does not certify a release. CI checks the digest, certificate contracts, the actual migration in isolated PostgreSQL WASM, legacy safety, flight/audio regressions and the production build. Deployment uses the checked-in public-registry npm lock and runs the Genesis checks before artifact upload.

## Required production certification

A trusted service operator must independently verify the exact deployment and evidence before recording any certificate. A digest or an HTTPS URL alone proves neither safety nor approval. The database trusts the service role as the issuing authority; never expose its credential to a browser. The implementation deliberately does not invent protected-route inventories, shared-world geometry, legal entitlement, consent or evidence.

1. Review/apply only `20261114120000_ares_genesis_certification_v11.sql` through the controlled migration process. Do not replay historical reset/resource-grant migrations. Verify actual production schema, membership/auth behavior and RLS in staging first.
2. Capture the global snapshot through service-only `ares_genesis_world_snapshot_v11()`. Review every physical building, fixed obstacle, protected walking/entrance route, other reservation, the complete V11 envelope, legal campus entitlement and the release-bound terrain. Coordinate these inventories with the authoritative world owner. Empty inventories are valid only when independently established as complete.
3. Archive real world, terrain, reservation, browser/device, entitlement, release and reviewer evidence at an immutable HTTPS location. Hash the archived evidence bytes. Include current production schema and concurrency validation. Unit fixtures and old audio evidence are not production certification.
4. In a service-controlled transaction, revoke the old certificate if any, verify the fresh snapshot, and insert a new certificate for the intended colony with that snapshot, approved `site`, matching release digest, real evidence digest/location and bounded expiry. The `site` contains placement `{-516,-213,0}` as `{x,z,rotationY}`, true completeness/reservation flags, and `occupied`, `protectedRoutes`, `reservedCells`, `legalRegions` arrays. Do not remove building records or exclude occupied areas to obtain approval. Any failed check requires a new review.
5. Verify an authenticated intended-colony caller gets a current approval; anonymous, other-colony, expired/revoked and stale-world calls must fail closed. Confirm original Hub fallback, renewal, navigation, scene failure and live placement conflicts in staging before considering activation.
6. Resolve the outstanding release blockers below and obtain valid production certification before activation. No local command here issues a production certificate.

To withdraw approval, set its `revoked_at` through the service authority. Keep the reservation until the last 60-second lease drains before modifying conflicting geometry. Leave player buildings, resources, progression and flight untouched. Reverting the client release restores the original visual; certificate absence already does so without a database reset.

## Local verification and limits

Run `npm ci`, `npm run test:release`, and `npm audit`. The database integration test uses the exact migration against an isolated PGlite PostgreSQL instance with synthetic colony/evidence fixtures. It verifies authorization, immutable/revoked/invalid certificates, reservation enforcement, stale/ABA snapshots and existing-row preservation. It does not prove production schema compatibility or concurrent multi-session behavior. The terrain test uses the shipped height binary and production sampler, with explicitly synthetic entitlement flags.

Local results: 5 V11 certification/terrain tests, 6 legacy safety checks, 96 ARES flight/audio tests, 23 OAuth Node tests, 29 Deno security tests, coordinate-engine verification and the production build passed. The Chrome OAuth test skipped inside the filesystem sandbox, then passed when rerun outside it. The Docker-backed OAuth SQL suite also passed, including its four concurrent-claim check. These isolated fixtures are independent of production player data. Browser/device production certification evidence must still be obtained.

The dependency advisory query on 2026-11-14 reported 10 findings (4 high, 6 moderate), including Vite/build tooling and legacy Solana dependencies. They remain unresolved; no audit check was suppressed and no forced major-version migration was attempted. These findings and missing live certification prevent declaring this release production-certified.
